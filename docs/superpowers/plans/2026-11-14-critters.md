# Critters and eggs in zones Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the critters and eggs of a zone live (map, flock, population), with the game's crowding verdict and tested rule classes, plus critter feeding flows as the base for a later colony balance.

**Architecture:** The Uplink mod adds three zone sections: critters and crowding regions on the fast stream (5 s), eggs on the slow stream (30 s). The site parses them in one reader. Pure rule classes in `app/Services/GameRules/` compute crowding and feeding, and are checked against the game's verdict on ingest. Vue renders a map layer, a Population block and a flock.

**Tech Stack:** C# net48 + xunit (mod `~/dev/uplink`), Laravel 13 / PHP 8.5 / Pest, Spatie Data + TypeScript transformer, Vue 3 + Inertia v3, vite-plus tests, LaRecipe docs.

**Spec:** `docs/superpowers/specs/2026-11-14-critters-design.md` (read it first: the "What the game does" section is the source for every rule value below).

## Global Constraints

- Branch `feat/critters` in both repos (site already on it; create it in `~/dev/uplink`). Commits without Co-Authored-By and without GPG signature (`git -c commit.gpgsign=false commit`).
- Never `npm`/`npx`: `bun`, `bunx`. PHP: `vendor/bin/pint --dirty --format agent` before each commit touching PHP. `php artisan make:*` for new classes, `--no-interaction`.
- Vue SFCs use `<script setup lang="ts">`. Sections marked `<!-- region name -->` / `<!-- endregion -->` in templates and `// region name` in scripts.
- No hand-built URLs: Wayfinder imports. No hand-written game status names: names come from the game strings via `GameText`.
- New sections are **additive optional fields**: no `schema` bump (orchestration spec §5).
- Region ids: `cavity:{handle}` or `pond:{smallest instanceId among its fishes and eggs}`.
- Anything the planner computes rather than reads is marked `derived` (Data field `derived: bool`, MCP text "(derived)").
- Engine constants live in the rule class, as named constants: `FERTILITY_MULTIPLIER = -1.0`, `CONFINED_HAPPINESS = -10`. Per-critter values come from the DB (`critter_morphs.overcrowding_threshold`, diets, outputs).
- After changing Uplink listener/ingest PHP: `php artisan queue:restart` (workers loop in `php artisan dev`). After a mod change: `./build-and-install.sh` in `~/dev/uplink`, then tell the user to load the game. Don't ask before deploying the mod.
- Docs ship with each slice: run `php artisan larecipe:affected --uncommitted --base=main`, update pages with the `larecipe-update-docs` skill (new pages with `larecipe-write-docs` through the LaRecipe MCP author tools), `php artisan larecipe:validate`. Review mode is required: show the user the docs diff before committing it.

```json
  "statuses": [{"id": "Cramped", "bad": true}], "effects": [{"id": "FutureOvercrowded", "bad": true}],

"crowding": [{
  "id": "pond:1201", "kind": "pond", "cellCount": 104, "occupied": 88, "eggOccupied": 24,
  "counts": {"Pacu": 11},
  "states": {"Pacu": {"overcrowded": false, "cramped": true, "confined": false, "modifier": 0}}

```

Slow message, new key after `temperature`:

```json
"eggs": [{
  "instanceId": "5678", "prefabId": "PacuEgg", "cell": 133900, "incubation": 38.0, "viability": 100.0,
  "tame": true, "spawns": "PacuBaby", "location": "floor", "holderId": null, "regionId": "pond:1201"
}]
```

Any value the game does not expose for that entity is `null`, and any list it lacks is `[]`. `happiness.state` is one of `happy|neutral|glum|miserable`, `location` one of `floor|incubator|storage`, `kind` one of `cavity|pond`, `facing` one of `left|right`.

## Review Focus

1. **Eggs lag critters by up to 30 s.** The consistency check must not flag a mismatch because the slow egg list is older than the fast region. Expected: the check compares only critter-driven values (occupied, overcrowded, confined) and takes `eggOccupied` from the game. Test in Task 5.
2. **A critter carried by a duplicant or stored** (no path, region null, cell maybe outside the zone). Expected: it is not drawn as swimming, counts in no region, and the flock shows it once. Tests in Tasks 3 and 10.
3. **Session change / old save loaded.** Stale critters from another session must not mix in. Expected: the existing `StoreZoneState` session rule covers it, and the replay resets when the `instanceId` set changes. Test in Task 10.
4. **Zone with 0 critters, or a fast state from an older mod without `critters`.** Expected: "unknown" (key absent) differs from "none" (`[]`). The Population block and flock show an empty state that explains why, never a crash. Tests in Tasks 3 and 6.
5. **A region with an unknown prefab** (mod critter not in the DB, so no personal space). Expected: the game's numbers still show, the derived per-type removal is omitted for that type, and the consistency check skips it with a log rather than reporting a false mismatch. Tests in Tasks 4 and 5.

## Slice 2 — Overcrowding

### Task 4: `Overcrowding` rule class

**Files:**
- Create: `app/Services/GameRules/Critters/Overcrowding.php`, `app/Data/GameRules/OccupancyInputData.php`, `app/Data/GameRules/OccupantData.php`, `app/Data/GameRules/OccupancyVerdictData.php`, `app/Data/GameRules/CritterOverOccupancyData.php`
- Test: `tests/Unit/Services/GameRules/OvercrowdingTest.php`

**Interfaces:**
- Produces:
  - `OccupantData(string $prefabId, int $personalSpace, bool $aquatic, bool $confinementImmune)`. `OccupancyInputData(int $cellCount, bool $isPond, list<OccupantData> $critters, list<OccupantData> $eggs)`: for eggs, `personalSpace` is the hatched critter's space.
  - `Overcrowding::analyze(OccupancyInputData $input, int $personalSpace, bool $confinementImmune = false): OccupancyVerdictData`, from the point of view of a critter type (the game evaluates per critter).
  - `OccupancyVerdictData(int $cellCount, int $occupied, int $eggOccupied, int $free, bool $overcrowded, bool $cramped, bool $confined, int $happinessModifier, list<CritterOverOccupancyData> $perType)`. `CritterOverOccupancyData(string $prefabId, int $count, int $personalSpace, int $toRemove, bool $canFix, bool $derived)`.
  - Constants `FERTILITY_MULTIPLIER = -1.0`, `CONFINED_HAPPINESS = -10`.
- Rules (port of `OvercrowdingMonitor`, cite it in PHPDoc):
  - A land region (`isPond=false`) ignores aquatic occupants (`excludeFish`). A pond counts only aquatic ones.
  - `occupied = Σ personalSpace(critters)`, `eggOccupied = Σ personalSpace(eggs)`.
  - Degenerate when `personalSpace == 0`: all states false, modifier 0.
  - `overcrowded = cellCount - occupied < 0`. `cramped = cellCount - occupied - eggOccupied < 0 && eggOccupied > 0`. `confined = !immune && cellCount < personalSpace`.
  - `happinessModifier = overcrowded ? -ceil((occupied - cellCount) / personalSpace) : 0`.
  - `perType`: for each critter prefab, `toRemove = min(count, ceil(over / space))`, `canFix = ceil(over / space) <= count`. Here `over = occupied - cellCount` when overcrowded (`derived=false`), else `occupied + eggOccupied - cellCount` when cramped (`derived=true`). Empty when neither. Sorted by `count × space` descending, as the game does.

- [ ] **Step 1: Write failing tests** with these exact cases:
  - `it is not crowded below the limit`: 104 cells, 11 Pacus at 8 → occupied 88, free 16, all false.
  - `it is cramped when eggs would overflow and derives the removal`: + 3 eggs at 8 → eggOccupied 24, cramped true, overcrowded false; perType Pacu `toRemove=1, canFix=true, derived=true`.
  - `it is overcrowded and gives the game's removal count`: 80 cells, 11 Pacus at 8 → over 8, modifier −1, Pacu `toRemove=1, derived=false`.
  - `it rounds the removal up`: 80 cells, 11 at 8 + 1 at 12 → over 20, per type ceil(20/8)=3 capped at 11, ceil(20/12)=2 capped at 1 → `canFix=false`.
  - `it is confined in a region smaller than one critter`: 5 cells, space 8 → confined; with `confinementImmune=true` → not confined.
  - `it ignores fish in a land cavity and land critters in a pond`.
  - `it is never crowded with zero personal space`.
