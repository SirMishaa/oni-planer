# In-game chat with Claude Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rebindable shortcut in Oxygen Not Included opens a chat panel; the player asks about a machine or an area, the context (selection, zones, boxes, rooms, a capture) leaves with the question, and a read-only Claude Code (`claude -p`) answers in the panel.

**Architecture:** The mod sends `client-chat.ask` (reliable) with references and geometry only. The site stores the question, creates **transient zones** for the boxes, rooms and objects it has no data for, and asks the mod to sample them once through a `chat.context` command; the mod answers with the normal `client-zone.layout/slow/fast/capture` messages, so the existing ingestion stores them. A queued job waits for that data, builds the prompt and calls a Laravel AI SDK agent whose provider (`claude-code`, registered with `Ai::extend`) runs `claude -p`. Replies go back to the game as `chat.reply` commands on the existing command channel.

**Tech Stack:** Laravel 13 / PHP 8.5, `laravel/ai` ^1.4 (custom provider), Pest, Reverb (existing Uplink transport); mod C# net48, Harmony, PLib 4.15, xunit (`Uplink.Core.Tests`).

**Spec:** `docs/superpowers/specs/2026-11-18-in-game-chat-design.md`

## Global Constraints

- Read-only Claude: `claude -p` gets `--tools "Read,Grep,Glob,Bash"`, `--permission-mode dontAsk`, `--allowedTools` limited to `mcp__oni__*`, `Read`, `Grep`, `Glob`, `Bash(ilspycmd *)`, `Bash(rg *)`, and `--strict-mcp-config --mcp-config` with the `oni` server only. Never `--dangerously-skip-permissions`. Check each flag against `https://code.claude.com/docs/en/cli-reference.md` and `permissions.md` (Markdown versions) before relying on it; adjust the exact rule syntax there, not the intent.
- `request_capture` is allowed (it is in `mcp__oni__*`); nothing else that writes or sends commands.
- `claude -p` runs with the site repo as working directory, as the queue worker's user (the player's Claude login). No API key.
- Conversation continuity: first question of a conversation runs with `--session-id <uuid>` generated by the site; later questions with `--resume <uuid>`; when resume fails, rerun once with a fresh `--session-id` and the previous Q&A replayed in the prompt.
- A question runs in a queued job (queue `chat`), never in a request or in the Reverb listener. Timeout of the `claude` process: 300 s (`config('ai.providers.claude-code.timeout')`). Context wait: 20 s.
- One question at a time per conversation: the mod disables Send while a question is pending.
- **Transient zones** (plan decision, deviates from the spec's "not as a zone" wording to reuse ingestion, captures and MCP tools unchanged): `zones.transient = true`, excluded from `scopeActive()`, from `SyncZoneList` archiving and from `ResyncZoneWithoutLayout`; resolvable by numeric id in `McpZones::resolve` only. Never shown in zone lists or pages. The mod never stores them in `ZoneStore`.
- Layer filters are a hint only: stored on the context item, written in the prompt, never used to filter data.
- Mod panel strings in English in a `ChatStrings` class (like `ZoneToolStrings`); Claude answers in the player's language.
- PHP: `declare(strict_types=1)`, curly braces, typed signatures, PHPDoc array shapes, `vendor/bin/pint --dirty --format agent` before each commit, Octane rule: no request state in singletons (use `scoped()`).
- `php artisan queue:restart` after PHP changes when testing by hand (workers loop in `php artisan dev`).
- Package manager: `bun`, never `npm`. Commits: no `Co-Authored-By`, no GPG signature (`git -c commit.gpgsign=false commit`).
- Mod build/install: `~/dev/uplink/build-and-install.sh`; core tests: `dotnet test ~/dev/uplink/Uplink.Core.Tests`.
- Docs ship with the code (LaRecipe): before pushing, `php artisan larecipe:affected --uncommitted --base=main`, update with `larecipe-update-docs`, `php artisan larecipe:validate`, and show the docs diff to the user before committing it.

## Review Focus

1. **Game offline or a different save loaded when the question arrives** → the context wait times out; Claude still answers from stored data and the answer says what could not be read. Test in Task 5.
2. **`claude` missing from PATH, not logged in, or exiting non-zero** → the panel gets an error reply with the process's first stderr line, never silence. Test in Task 1 and Task 5.
3. **Resume of a deleted or unknown Claude session** → one retry with a new session id and the replayed transcript. Test in Task 1.
4. **A box or room on another world (Spaced Out) or with zero valid cells** → the mod refuses that item in its `chat.context` ack reason; the job does not wait for it. Test in Task 7 (core) and Task 5.
5. **The same `client-chat.ask` delivered twice (reliable resend)** → one question, one answer. Test in Task 4.
